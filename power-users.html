For power users

Clean up data at scale, without a migration project

Bulk changes stage the same way schema and security changes do — reviewed and diffed before they touch a single live record.

Bulk data changes

Staged and reversible, not a one-off script

Cleanup that runs against live writes

A bulk transformation runs as a continuous process against the live write stream, not a one-time batch job, and stages into an overlay you can browse and diff before/after per item. Discarding it costs nothing — live data is never touched until you commit.

Traits without a ticket to engineering

Traits let you add or remove capability from a type non-destructively. Existing items simply return null for new properties until populated, and most changes — new properties, renamed labels, added traits — don't even bump the schema version.

Exploring your data

Relationships you can actually query

Not navigation-only edges — links are indexed, labeled, and built for retrieval.

Independently labeled links

A Photographer might see a "created" link to a Photo, while the Photo sees the same link as "creator" — each participant's own view of the relationship.

Multi-hop traversal

Traversal up to roughly five hops runs efficiently via recursive queries — covering the practical depth of real queries without a separate graph-traversal tool.

Canonical records, governed

Master data management for the entities your business runs on — customers, products, vendors — with security markers and the same staged changeset model for safe bulk cleanup.
