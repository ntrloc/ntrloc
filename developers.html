For developers

A schema you can trust, not one you have to guess at

A typed, self-describing API and a staging model you can query and test against before anything touches live data — no local mocks standing in for the real thing.

Local development

Runs on your laptop, not just in a shared cluster

The same binary that scales out to a Kubernetes cluster runs as a single instance on a laptop. There's no separate "local mode" that drifts from what you deploy — you get a real schema, real permissions, and a real staged overlay to iterate against from the very first run, not a stripped-down emulator standing in for the real thing.

API & schema

No trial and error

The schema you're handed is a complete, accurate contract for what you can actually do.

Caller-scoped by default

The schema endpoint returns a projection scoped to the caller: item types you can't see are omitted entirely, properties appear only if you have read or write access to them (and the response says which), and link types appear only when both participant types are visible to you.

Typed items, links, and traits

Items, links, and reusable traits, with per-type storage for read performance. Properties are stored keyed by immutable property IDs rather than human-readable labels, so a rename on the backend is a metadata change — never a breaking change in your integration.

Build and test against the real overlay, not a local mock

Any schema, security, or bulk data change stages as a live overlay before it's committed. That overlay is queryable like any other view — you can diff before/after per item and exercise a pending change against real data shapes without ever writing to live state, and discarding it costs nothing.

What you get

Built to keep the API stable while the schema underneath moves

Relationships you can query

Undirected links with independently labeled participant slots, and multi-hop traversal up to roughly five hops via recursive queries — no dedicated graph-traversal engine required.

Binary data, handled for you

Binary properties are deduplicated by content hash on upload. ntrloc is always the pass-through for downloads, so you never handle a raw storage path, and every download is permission-checked and audited.

Non-destructive schema changes

Adding a trait to a type is non-destructive — existing items simply return null for the new properties until populated. Most schema changes don't even bump the schema version.

On the roadmap

Scripted, dynamic controllers

Custom server-side endpoint logic as scripts — via the standard Java Scripting API, with Groovy and GraalVM JavaScript as the planned bundled defaults — and no compile-and-deploy cycle to add or change one. Conceptual design only; not yet built. See the roadmap for details.
