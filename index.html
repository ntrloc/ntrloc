Why ntrloc

Four things most data platforms treat as your problem

ntrloc treats them as its own.

Graph-native modeling

Items, links, and reusable traits — with per-type storage for read performance and undirected links with per-participant visibility. No shoehorning a graph into rows and foreign keys.

See the model →

Built for uptime

Schema, security, and bulk data changes stage as a live overlay, diffed and reviewed, then flip to live in a single atomic switch. UI, templates, and scripts resolve hot — nothing requires a restart to ship.

See how it works →

Schema evolution without the drama

Traits let you add or remove capability from a type non-destructively. Most schema changes — new properties, renamed labels, added traits — don't even bump the schema version.

See schema evolution →

Security as a primitive

Policy markers, declarative rule-based assignment, and time-bounded overrides. Callers only ever see the schema and data they're actually permitted to touch.

See the security model →

What you can build

One platform, different systems

The same graph, trait, and security primitives underneath each of these.

Master data management

Canonical, governed records for the entities your business runs on — customers, products, vendors — with security markers and a staged changeset model for safe bulk cleanup instead of a risky one-off migration.

Digital asset management

Binary properties are deduplicated by content hash, and the security model was shaped around exactly this kind of catalog — cover images, embargoed campaigns, per-participant visibility on every relationship.

Issue tracking

Typed items and undirected links model tickets, relationships, and ownership directly, while the embedded BPMN engine handles status transitions and routing — deployable live, no release cycle.

Case management

A case is just an item with a rich web of related items and links, governed by the same markers and audit trail as everything else — with ad hoc, non-linear process support (CMMN) planned alongside today's BPMN engine.

And more

Also in the platform

Not headline features on their own, but part of what makes ntrloc a platform rather than just a database.

Projections & faceting

Cross-type queries are trait-constrained and pushed down as partial aggregation across each participating type's table, so faceted search stays fast across a union of types.

Built-in observability

OpenTelemetry instrumentation and log correlation ship in the platform itself — traces and logs from day one, not bolted on by every team that deploys it.

LDAP & OAuth2/OIDC

Authenticate against an LDAP directory or any OAuth2/OIDC provider. SSO is handled at the identity provider — ntrloc extracts only a stable identifier.

Runs anywhere, scales out

From a single instance on a laptop to a massive Kubernetes cluster — built from day one with ephemerality in mind, so nodes can come and go without ceremony. Per-type storage keeps reads fast as data grows, and changeset builds run across the cluster in parallel rather than on a single node.

UI hosting

ntrloc hosts your app's UI too — static SPA bundles and server-rendered modules — not just a data API you have to host somewhere else.

Hot-deployable process definitions

An embedded BPMN engine with a visual editor. Deploy a new process version live — no restart, no release cycle.

Federated supergraph Coming soon

Query across independently deployed domains, each enforcing its own policy on its own data — in active development.

Append-only audit ledger

Every mutation — data, schema, or security — is recorded in an append-only ledger, giving you a verifiable history of who changed what, when, and why.

Built for real constraints

For teams who can't afford a bad migration

Bulk schema and security changes are exactly the moments platforms fail loudest — a migration half-applies, a permission rule fires wrong, and it's live before anyone notices. ntrloc's changeset model exists to make that specific failure mode structurally impossible: you review the actual post-change result against live data before it ever becomes live data.
